# LeanLife 减脂饮食规划项目

这是一个可直接打开运行的前端原型，用来验证减脂饮食规划产品的核心方向。

## 当前原型包含
Title
记餐 · 观变 · 调策
Log · See · Adjust

1. 主流减脂饮食方案库
   - 均衡热量缺口
   - 高蛋白减脂
   - 地中海式减脂
   - 低碳减脂
   - 轻断食（16:8）
   - 高体积低密度饮食

2. 身体数据与生活习惯评估
   - BMI
   - BMR（基础代谢）
   - TDEE（总消耗）
   - 围度估算体脂率
   - 腰高比
   - 恢复分、依从性基础分、代谢准备度
   - 蛋白质 / 脂肪 / 碳水建议

3. 日历化身体反馈追踪
   - 按日期记录体重、腰围、能量、饥饿感、执行度
   - 自动生成近 7 次记录的洞察
   - 数据保存在浏览器 localStorage

4. 食物营养与热量计算
   - 内置常见减脂食物营养数据库
   - 按食物重量自动换算热量、蛋白质、脂肪、碳水、膳食纤维
   - 将每日摄入与当前饮食方案的目标热量和宏量营养做对比
   - 把营养达标率接入日历评分和追踪洞察

5. 每日建议餐单生成
   - 根据当前饮食方案、目标热量和食物数据库生成一天餐单
   - 按早餐 / 午餐 / 晚餐 / 加餐拆分建议
   - 支持一键把建议餐单加入当日食物记录

## 使用方式

直接在浏览器中打开 `index.html` 即可。

## 多用户轻商用过渡骨架

为了把当前前端原型稳定过渡到轻商用、多用户版本，项目中已经补了一套后端基础骨架：

1. `docs/multi-user-mvp-architecture.md`
   - 说明多用户 MVP 的系统拆分、业务分层、合规边界与推荐迭代顺序

2. `backend/schema.sql`
   - 提供 PostgreSQL 数据结构骨架，覆盖用户、档案、评估、日历记录、食物记录、营养快照与推荐快照

3. `backend/openapi.yaml`
   - 提供多用户阶段最关键的 API 契约，包括注册登录、档案、评估、日历记录、饮食记录、营养分析与趋势接口

4. `backend/src`
   - 提供后端模块职责骨架与 TypeScript 合同文件，清楚划分 `auth / profile / assessments / tracking / nutrition` 的边界，方便多人协作和后续 Codex 接手

5. `frontend`
   - 提供基于 Next.js App Router 的多用户工作台前端骨架，并已经接上 `Next API -> backend HTTP API` 的真实 demo 链路
   - 当前工作台支持：档案更新、重新评估、当日追踪写入、食物记录写入、营养分析与补缺口建议展示

6. `frontend/src/app/api/workspace/*`
   - 这是浏览器层和后端层之间的内部代理层
   - 浏览器只访问前端自己的 `/api/workspace/*`
   - Next 层再统一去访问后端真实接口，减少前端直接耦合后端细节

这一步的价值是先把“前端原型”升级成“可接后端的产品骨架”，后续不管是做 React/Next.js、NestJS 还是 FastAPI，都可以直接基于这套数据与接口边界继续开发。

## 当前可运行的 Demo 链路

目前项目里已经能跑通两条链：

1. 静态高保真原型
   - 直接打开 `index.html`

2. 多用户工作台 Demo
   - 启动 `backend`
   - 启动 `frontend`
   - 打开 Next.js 工作台页面
   - 通过前端工作台直接驱动 `auth -> profile -> assessments -> tracking -> nutrition`

## 下一步建议

1. 升级为前后端分离项目
   - 前端：React / Next.js
   - 后端：Node.js / NestJS 或 Python / FastAPI
   - 数据库：PostgreSQL

2. 增加真实产品能力
   - 用户注册与档案管理
   - 每日饮食记录与食物数据库
   - AI 饮食建议与动态调整
   - 图表趋势分析
   - 经期、睡眠、压力、训练负荷联动
   - 教练端管理后台

3. 提升算法严谨度
   - 引入更多体脂估算方式
   - 接入体成分秤 / Apple Health / 华为健康等设备数据
   - 使用滚动均值处理体重波动
   - 根据依从性与饥饿感动态调整热量缺口
